# Livestream Host Copilot 面试题库 v0.1

> 范围：实时 Agent 系统。RAG 仅作为外部可插拔 Tool，不考察其内部 Chunking、Embedding、Rerank 实现。
>
> 使用方式：先回答主问题，再根据“追问”继续深挖。参考要点不是背诵稿，回答必须结合业务约束、取舍和可验证指标。

## A. 基础知识与后端八股（A01-A15）

| ID | 难度 | 问题 | 参考答案要点 | 追问 |
|---|---|---|---|---|
| A01 | 基础 | 生产者-消费者模型是什么？在本项目中分别是谁？ | Audience Stream 是生产者；Normalizer、Router、Worker 是消费者；队列解耦流量和处理能力。 | 消费速度低于生产速度怎么办？ |
| A02 | 基础 | 什么是背压？为什么直播 Agent 必须有？ | 下游过载时限制、延迟或丢弃低价值任务，保护高价值链路；否则队列无限增长且回复过期。 | 背压和限流有什么区别？ |
| A03 | 基础 | 为什么需要消息 TTL？ | 直播问题具有时效性；过期低价值消息继续生成只会浪费成本并污染 Host 队列。 | 投诉消息也应该过期吗？ |
| A04 | 进阶 | 如何保证消息处理幂等？ | 使用 event_id/idempotency_key；消费记录、结果去重、Tool 读写分离；重试不重复产生建议或动作。 | Exactly-once 是否真的能做到？ |
| A05 | 基础 | P50、P95、P99 分别说明什么？ | 中位体验、长尾体验和极端尾部；直播 Agent 更关注 P95/P99 与过期率。 | 平均延迟为什么可能骗人？ |
| A06 | 进阶 | 重试应该怎么设计？ | 只重试瞬时错误；指数退避加抖动；限制次数；尊重总延迟预算；不可重试业务错误。 | 为什么 Judge 失败不能无限重写？ |
| A07 | 进阶 | Circuit Breaker 解决什么问题？ | 外部 Tool/RAG 连续失败时快速失败，避免线程和连接耗尽；半开探测恢复。 | 熔断后用户看到什么？ |
| A08 | 基础 | 什么是优先级队列？本项目优先级由什么决定？ | 按 business value、risk、freshness、cluster heat 排序；高风险可能优先人工而非优先生成。 | 如何防止低优先级消息永远饿死？ |
| A09 | 进阶 | 缓存价格和库存有什么风险？ | 动态事实易过期；需短 TTL、版本/时间戳和失败时保守回答；不能把缓存摘要当真值。 | 哪些信息适合长缓存？ |
| A10 | 基础 | 同步 I/O 与异步 I/O 如何选择？ | 多个远程只读 Tool 调用适合异步并行；有依赖关系或写操作必须保持顺序。 | 并行调用会带来哪些新问题？ |
| A11 | 进阶 | 状态机对 Agent 有什么价值？ | 显式表示路由、等待工具、重写、降级、人工确认和终止，支持恢复与回放。 | 为什么不能只靠 while loop？ |
| A12 | 基础 | Schema 校验解决什么问题？ | 限制模型生成的工具名、参数类型和枚举；在调用业务系统前阻断无效或越权请求。 | Schema 正确是否代表调用安全？ |
| A13 | 进阶 | At-least-once 消费会带来什么问题？ | 消息可能重复，需要幂等消费、去重和可重复执行的 Tool 契约。 | 如何处理乱序事件？ |
| A14 | 进阶 | 什么是结构化日志和分布式 Trace？ | 日志记录事件；Trace 用 trace_id/span_id 串联一次消息的跨节点路径、耗时、状态和错误。 | 高并发下如何控制 Trace 成本？ |
| A15 | 进阶 | 单元、集成、E2E 测试在本项目各测什么？ | 单元测评分/路由/权限；集成测 Router-Tool-Judge；E2E 测消息到 Host 建议和降级。 | LLM 非确定性测试怎么写？ |

## B. LLM 与 Agent 八股（B01-B15）

| ID | 难度 | 问题 | 参考答案要点 | 追问 |
|---|---|---|---|---|
| B01 | 基础 | LLM API 为什么说是无状态的？ | 每次调用只知道本次传入上下文；会话状态、记忆和任务进度由应用保存和重建。 | 无状态有什么工程优势？ |
| B02 | 基础 | Agent 与普通 LLM 调用的区别是什么？ | Agent 有目标、状态、工具、观察-行动循环、停止条件和系统级约束。 | 本项目哪些请求其实不需要 Agent？ |
| B03 | 基础 | Function Calling 和 Tool Calling 的关系是什么？ | 模型输出结构化调用意图；应用校验、授权、执行并返回 observation，模型本身不直接执行。 | 为什么模型不能自授权？ |
| B04 | 进阶 | ReAct 的核心循环是什么？ | Reason/Plan -> Action -> Observation -> next decision，适合事实不足且需外部工具的问题。 | ReAct 最大的线上风险是什么？ |
| B05 | 进阶 | CoT 和 ReAct 的区别？ | CoT 主要做内部推理；ReAct 将推理与外部行动交替；事实依赖任务优先 ReAct。 | 为什么不向用户展示完整 CoT？ |
| B06 | 进阶 | ToT 与 Best-of-N 有什么区别？ | ToT 有分支、评估、扩展和剪枝；并行生成 N 个完整答案再选优属于 Best-of-N。 | 本项目为什么只做浅层候选搜索？ |
| B07 | 基础 | 什么是 Model Routing？ | 根据任务复杂度、风险、语言和预算选择规则、轻量模型或主力模型。 | Router 本身失败怎么降级？ |
| B08 | 进阶 | Context Engineering 与 Prompt Engineering 有何区别？ | Prompt 关注指令表达；Context Engineering 关注选择、组织、更新、压缩和隔离模型可见信息。 | 本项目最重要的上下文字段有哪些？ |
| B09 | 进阶 | Agent Memory 有哪些类型？ | 工作记忆、会话/情景记忆、语义记忆和用户偏好；本项目重点是直播状态而非无限用户画像。 | 为什么不长期保存所有聊天？ |
| B10 | 进阶 | 什么是 Grounding？ | 回答受 Tool/RAG 证据约束，可引用、可验证；不是仅在 Prompt 里要求“不要幻觉”。 | 有证据仍然可能答错吗？ |
| B11 | 进阶 | Prompt Injection 与 Jailbreak 有什么区别？ | Injection 利用不可信上下文改变系统行为；Jailbreak 试图绕过模型安全策略；都需系统层防护。 | 商品文档里出现恶意指令怎么办？ |
| B12 | 进阶 | LLM-as-a-Judge 有哪些偏差？ | 位置、长度、风格、自洽和同模型偏差；需规则校验、随机顺序、明确 rubric 和人工校准。 | Judge 应看到候选来源吗？ |
| B13 | 基础 | Temperature 如何影响本项目？ | Router/结构化调用偏低温确保稳定；候选表达可适度提高；事实不能靠提高随机性获得。 | 三候选为什么不只改 temperature？ |
| B14 | 进阶 | Agent Loop 如何终止？ | 成功、无可用工具、达到步骤/Token/时间预算、重复调用、风险升级或人工接管。 | 如何检测循环调用同一工具？ |
| B15 | 进阶 | 什么是 Agent Harness？ | 为模型提供上下文、工具、权限、执行、Trace、评测和恢复能力的系统外壳。 | Harness 与业务 Workflow 如何分层？ |

## C. 项目架构与核心链路（C01-C20）

| ID | 难度 | 问题 | 参考答案要点 | 追问 |
|---|---|---|---|---|
| C01 | 基础 | 用 30 秒介绍这个项目。 | 一万观众、回复率不足 10%；消息分层；Tool/RAG Grounding；ReAct+Judge；Host HITL；评测闭环。 | 这个项目最核心的业务指标是什么？ |
| C02 | 进阶 | 从消息进入到主播看到建议，完整链路是什么？ | Normalize -> Filter/Cluster -> Router -> Scheduler -> Context -> Path -> Judge -> Host Queue -> Feedback/Trace。 | 哪些是主链路，哪些是横切能力？ |
| C03 | 深挖 | 为什么不把每条消息都送给大模型？ | 10k 观众、10-30 msg/s 平均和峰值放大；成本、延迟、噪声、主播认知容量不允许。 | 过滤错了会不会漏掉购买意图？ |
| C04 | 深挖 | Router 的输入输出契约是什么？ | 输入标准化消息、市场、语言和轻量上下文；输出 intent、value_score、risk_level、route、confidence。 | confidence 低时怎么处理？ |
| C05 | 深挖 | 意图 taxonomy 如何设计？ | 闲聊、商品咨询、价格库存、购买意图、配送、退换货、投诉、风险；支持多标签和层级。 | 单标签分类为什么不够？ |
| C06 | 深挖 | Business Value Score 如何计算？ | 购买意图、商品相关性、可售性、热度、互动阶段、时效；规则可解释，LLM 只提供特征。 | 权重如何标定？ |
| C07 | 深挖 | risk_level 为什么不能简单从 value_score 扣除？ | 高价值高风险消息仍需优先处理，只是进入 Judge/HITL；价值和风险是两个正交维度。 | 投诉应进入哪条路径？ |
| C08 | 深挖 | 消息聚类有什么业务价值？ | 合并重复问题、计算热度、支持主播一次口播覆盖多人、减少 LLM 调用。 | 聚类错误如何影响回复？ |
| C09 | 深挖 | Priority Scheduler 如何避免建议淹没主播？ | 每分钟 3-6 条预算、队列上限、TTL、价值排序、相似建议替换和已回答抑制。 | 高峰时丢弃策略是什么？ |
| C10 | 进阶 | Fast Path、Tool/RAG Path、ReAct Path 如何选？ | 按复杂度、事实依赖、风险和延迟预算；简单问题不进入循环。 | 哪些问题绝不能走纯生成？ |
| C11 | 深挖 | Context Builder 为什么独立于 Router？ | Router 要轻快；Builder 负责数据权限和任务化装配，职责、成本和变化频率不同。 | Builder 如何防止上下文污染？ |
| C12 | 深挖 | 两层上下文压缩分别解决什么？ | 大结果外置解决局部膨胀；结构化会话摘要解决长期历史；均保留 ref_id 和最近原文。 | 摘要错误如何恢复？ |
| C13 | 深挖 | 哪些信息不能被压缩进摘要？ | 价格、库存、优惠、有效政策等强事实；应按需重新查询并保留版本时间。 | 主播已经说过的价格怎么办？ |
| C14 | 进阶 | RAG 在这个系统中的边界是什么？ | 外部可插拔知识 Tool；Agent 管调用和证据消费，不实现 RAG 内部技术。 | RAG 不可用时如何降级？ |
| C15 | 深挖 | 为什么价格库存不用 RAG？ | 高频变化且要求强一致；语义检索不能保证最新和唯一真值，应查询结构化业务 API。 | Tool 超时能否使用旧值？ |
| C16 | 深挖 | ReAct Loop 内有哪些预算？ | 最大步骤、总延迟、Token、Tool 次数、重复调用检测和风险阈值。 | 达到预算仍无答案怎么办？ |
| C17 | 深挖 | 三候选分别是什么策略？ | factual、conversion、engagement；共享事实约束，不只是随机改写。 | 为什么不是三种人格？ |
| C18 | 深挖 | Judge 为什么必须在 Loop 外？ | 避免生成模型自我确认；便于独立规则、Trace、回放和替换；失败返回结构化 reason。 | Judge 失败如何重写？ |
| C19 | 进阶 | Host Queue 应展示哪些信息？ | 原消息/聚类、意图、候选、翻译、依据、风险、时间；支持采用、编辑、忽略。 | 展示太多会不会更打断主播？ |
| C20 | 深挖 | 系统的最终瓶颈是什么？ | 不只是模型吞吐，而是主播每分钟可理解和采用的建议数；系统需优化决策密度。 | 如何衡量认知负担？ |

## D. 多市场、安全、可靠性与评测（D01-D10）

| ID | 难度 | 问题 | 参考答案要点 | 追问 |
|---|---|---|---|---|
| D01 | 深挖 | `sales_market`、`delivery_market`、`locale` 有何区别？ | 分别控制商品促销、配送政策和表达语言；三者不能互相推断。 | 三个值冲突时谁优先？ |
| D02 | 深挖 | 多语言系统为什么不能只做翻译？ | Router、检索、安全、术语、生成和 Judge 都有跨语言误差，必须按语言切片评测。 | Code-switching 怎么处理？ |
| D03 | 深挖 | 五层安全权限是什么？ | 输入、上下文、工具、输出、HITL/审计；模型不能自我授权。 | 哪层负责 Prompt Injection？ |
| D04 | 深挖 | Tool Gateway 做哪些工作？ | Allowlist、Schema、market scope、脱敏、timeout、retry、breaker、audit。 | 只读工具是否就没有风险？ |
| D05 | 深挖 | 如何防止错误国家或过期政策？ | 调用 RAG 时强制 market/effective_at/policy_type；Judge 核对 metadata 和引用。 | 本地语言文档缺失怎么办？ |
| D06 | 深挖 | 如何评测 Router？ | Macro-F1、各语言切片、高价值 Recall、高风险 Recall、混淆矩阵和置信度校准。 | 为什么不用整体 Accuracy？ |
| D07 | 深挖 | 如何评测端到端回复质量？ | Groundedness、事实错误、安全、语言、采纳率、编辑率、响应时间；离线与在线结合。 | 自动指标与人工评分冲突怎么办？ |
| D08 | 深挖 | 如何把 Agent 建议和转化提升关联起来？ | 记录 suggestion_id 到曝光、采用、发送、点击、加购；A/B Test 控制活动和流量差异。 | 能否直接说转化提升由 Agent 导致？ |
| D09 | 深挖 | Trace 应记录哪些 Span？ | normalize、cluster、route、queue、context、model、tool、judge、host action；记录版本、耗时、Token、reason。 | 是否保存完整用户文本？ |
| D10 | 深挖 | 单场一万观众如何压测？ | 100 msg/s 持续、300 msg/s burst；多语言分布、重复热潮、Tool 故障、队列过载和 P95/P99。 | 通过压测的标准是什么？ |

## E. 压力面试与简历防守（E01-E10）

| ID | 难度 | 问题 | 参考答案要点 | 追问 |
|---|---|---|---|---|
| E01 | 压力 | 这不就是分类器加 Prompt，为什么叫 Agent？ | 复杂路径具备状态、动态工具选择、observation、循环、停止和恢复；同时承认多数消息不需要 Agent。 | Agent 比例只有 1%-3%，项目是否名不副实？ |
| E02 | 压力 | 你是不是为了面试硬塞了 ReAct、ToT 和五层权限？ | 每个机制必须有触发条件；简单消息 Fast Path；候选搜索只用于高价值；权限对应真实业务风险。 | 删除哪个机制影响最小？ |
| E03 | 压力 | 三个候选再选一个，明明不是 ToT。 | 承认是 ToT-inspired shallow search/Best-of-N；不用术语夸大，强调策略分支和 Judge 剪枝。 | 为什么简历还要写 ToT？ |
| E04 | 压力 | Judge 也是 LLM，凭什么更可信？ | 强事实由规则核验；LLM Judge 只补语义维度；独立 rubric、人工校准、失败降级。 | Judge 和 Generator 用同一模型行不行？ |
| E05 | 压力 | 回复率从不足 10% 提升到多少？ | 当前只有基线；目标 25%-35% 有效问题、高价值 60%-75%；必须以实验结果替换目标。 | 没有线上数据为什么写简历？ |
| E06 | 压力 | 转化率提升怎么证明不是主播或活动造成的？ | 随机化 A/B、分层、足够样本、统一口径；只报告置信区间和相关限制。 | 无法 A/B 时怎么办？ |
| E07 | 压力 | 为什么不直接让主播看按热度排序的消息？ | 排序解决发现，不解决多语言理解、事实查询、组织回复和安全校验；但应作为 baseline。 | Agent 必须超过哪些 baseline？ |
| E08 | 压力 | 系统最可能在线上失败在哪里？ | Router 漏召回、market 错配、Tool 超时、旧事实、队列过载、Judge 漏检、Host 不采纳。 | 你先监控哪个指标？ |
| E09 | 压力 | 哪些数字可以写进简历？ | 真实业务基线、实际压测、Golden Dataset 和 A/B 结果；设计目标必须标明，不可冒充结果。 | 测试集是谁标注的？ |
| E10 | 压力 | 如果只能保留三个亮点，你选什么？ | 高并发价值路由；EU 多市场 Tool/RAG Grounding 与五层权限；Trace+评测闭环。 | 为什么不选多语言或 ToT？ |

## 推荐学习顺序

1. 先掌握 C01-C10，能完整讲清业务、链路和路由。
2. 学习 A01-A15，补齐队列、背压、重试、熔断和 Trace 基础。
3. 学习 B01-B15，明确 Agent 术语及适用边界。
4. 深挖 C11-D10，形成上下文、安全、多市场和评测能力。
5. 最后使用 E01-E10 做压力面试，检查简历表述是否经得住追问。
